Why June?

Persistent memory

Every conversation feeds a shared memory. June remembers your preferences, goals, and context across sessions — no more starting from scratch.

Local-first

Runs on your machine via Ollama + Gemma 4. No cloud dependency, no data leaving your computer unless you choose to use Gemini.

Standing intentions

June tracks what you have asked it to keep in mind as standing intentions, and surfaces them when you return or the world genuinely changes — never on a timer, never unprompted noise.

Extensible skills

Calendar, health tracking, filesystem access, web research, and Telegram integration. Each skill is an MCP server — add or remove at will.

Privacy dial

Choose which conversations stay fully local and which can use cloud models. Your data, your rules.

Open source

MIT-licensed. No accounts, no surveillance, no vendor lock-in. June is built for you, not for a SaaS pipeline.

Your privacy, designed in

June was built from the ground up around a simple principle: your personal data belongs to you. The default configuration runs everything locally — no data ever leaves your machine.

  • Local by default — Gemma 4 runs on your machine via Ollama. No external API calls.
  • Cloud when you choose — Switch to Gemini for tasks that need more capability. The privacy dial lets you control which conversations go to the cloud.
  • No telemetry — June doesn't phone home. No analytics, no crash reporting, no user tracking.
  • Your data stays yours — Conversations, memory, and configuration live in a local SQLite database. Export or delete it anytime.
  • API key auth — The local HTTP API requires a key. No open ports, no accidental exposure.

June is open source under MIT. No ads, no accounts, no surveillance.
