JuneAI Architecture

JuneAI is a local-first Streamlit application with a LangGraph agent core, multi-runtime model support, and SQLite-backed memory. This page is the visual companion to docs/architecture/README.md.

Diagram 01

System Overview

The product has four active layers: the Streamlit shell, the UI helper modules, the LangGraph agent/runtime layer, and the SQLite memory store.

Diagram 02

One Turn Lifecycle

A single user turn builds prompt context, invokes the configured model, optionally executes tools, streams events back into the Streamlit shell, and persists memory.

sequenceDiagram actor U as User participant S as Streamlit Shell participant G as LangGraph Agent participant M as Memory participant L as Model Runtime participant T as Tool Layer U->>S: Send message S->>G: Start streamed turn G->>M: Build memory context M-->>G: Today summary / commitments / telemetry G->>L: Invoke runtime model alt Tool calls requested L-->>G: AI message + tool calls G->>T: Execute tool(s) T->>M: Read / write structured records M-->>T: Persisted result T-->>G: Tool messages G->>L: Re-invoke with tool results else Direct answer L-->>G: AI message only end G-->>S: Stream chunks + custom events S->>M: Save final conversation state S-->>U: Updated transcript + panels

Memory Domains

JuneAI stores structured records in SQLite rather than legacy JSON files. The memory layer is one database file with per-domain tables.
