# v0.1.1 Scheduled Development Plan

> **Status:** Superseded by the canonical [build specification](../product/build-spec.md)
> and [ADR 0015](../decisions/0015-center-of-gravity-four-inversions.md). The Quick
> Capture / Daily Home / operating-layer track described here is no longer the active
> direction; this document is retained for historical context only.

## Goal

v0.1.1 turns June from "chat with memory plus tasks" into the first usable
personal operating loop:

> User says anything. June captures it, understands it, proposes safe actions,
> remembers what matters, schedules what needs time, and brings it back in the
> daily flow.

The UI stays simple. The backend becomes more disciplined.

## Release Theme

**Quick Capture + Daily Home + Durable Intent Ledger**

The release is successful when a user can open June, dump a messy thought, and
see June convert it into the right mix of memory, task, promise, event, feeling,
or decision without losing trust.

## Non-Goals

- No paid infrastructure.
- No account system.
- No cloud sync.
- No full Gmail/OAuth build.
- No mobile app.
- No always-on audio.
- No workflow engine dependency beyond the existing SQLite scheduler.
- No large UI redesign.

### P3 — Quick Capture Backend

capture box on the home screen. Actually committing low-risk candidates (real
memory/task writes) moves to P4 alongside approval.

Deliverables:

- Add `POST /capture` and `GET /capture/recent`.
- Add a capture classifier that returns structured candidates.
- Add safe local writes for low-risk memory/task/promise candidates.
- Route writes through the event ledger.

Acceptance:

- "Tomorrow call Sam and finish the deck" becomes task/event candidates.
- "I promised Lisa the file Friday" becomes a promise candidate.
- "I am anxious about money" becomes a feeling record plus a practical support

## Golden Workflows

These workflows define the test matrix for the release.

1. **Natural planning**
   - Input: "Tomorrow I need to call Sam, finish the deck, and maybe go to the
     gym if I have energy."
   - Expected: tasks, optional agenda suggestions, no unwanted calendar write.

2. **Promise tracking**
   - Input: "I told Lisa I would send the file Friday."
   - Expected: promise, due date, follow-up candidate.

3. **Anxiety support**
   - Input: "I am anxious about money and feel stuck."
   - Expected: supportive response, optional memory, one small practical action,
     no therapeutic claim.

4. **High-energy planning**
   - Input: "I am going to take this app to the world."
   - Expected: vision capture, three concrete next actions, bounded schedule.

5. **Decision ledger**
   - Input: "Ship the unsigned DMG now and notarize later when users ask."
   - Expected: decision memory with reason and follow-up.

6. **Privacy dial**
   - Input: any capture requiring cloud classification while local-only is on.
   - Expected: blocked cloud call and local fallback or user-facing limitation.
