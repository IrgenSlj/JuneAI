## 1. Operating principles (binding for every slice)

1. **Everything on `main`.** Direct-to-main, no feature branches (repo convention +
   founder directive). Before each push: `git log`/`git status` sanity + check for
   concurrent Claude sessions on the shared checkout.
2. **Small validated slices.** One slice → `./tools/check.sh` green → one commit →
   push. No batching unrelated changes. A slice is the smallest thing that is
   correct, tested, and leaves `main` shippable.
3. **Push often.** Every green slice is pushed. The tree on `main` is always
   releasable.
4. **ADR before implementation.** Each architecture-changing workstream (W2, W3, W4,
   W5, W6, W1.4) gets its ADR drafted and committed *first* (numbers 0024–0029
   reserved). The ADR's context section is this brief.
5. **Graceful degradation ships in the same slice** as any model-judgment feature
   (fusion, injection heuristic, consolidation, classification) — never a follow-up.
6. **Privacy is visible in code.** Any new egress path (W1.4 update check, W6 ping)
   lands with its Trust-screen disclosure + settings off-switch in the same slice.
7. **Single store, single facade.** No new DB/service/daemon. All memory access
   through `MemoryManager`; add the import-linter/test guarding it (W2).
8. **No new heavyweight deps** without an ADR. Preference: stdlib > existing dep >
   small single-purpose lib > nothing. SQLite-native (FTS5, triggers, JSON1) beats
   a new service every time.

## 2. Delegation model

Orchestrator/worker split (Opus orchestrates on the main thread; Sonnet subagents
do bounded implementation), tuned per task:

- **Orchestrator (this thread):** planning, ADRs, schema design, reconciliation,
  cross-cutting decisions, review of every subagent diff, running `check.sh`,
  commits/pushes. Holds the invariants.
- **`implementer` subagents (Sonnet):** given an exact spec (files, signatures,
  the change, the tests to add), apply edits + run targeted verification, report a
  diff. Used for mechanical, well-scoped slices (migrations, DAO methods, a test
  fixture, a UI component wired to a known API).
- **`reviewer` subagents (Sonnet):** second pass on a diff before commit — bug
  hunt, missed cases, test gaps.
- **`Explore` subagents:** read-only fan-out for locating code (used heavily in W0.1).
- **Parallelize** independent slices (e.g. a migration + an unrelated UI test) by
  launching subagents concurrently; serialize anything sharing a file or schema.

Rule: a subagent never decides an invariant or a privacy boundary — those stay on
the main thread. Every subagent diff is reviewed here before it is committed.
