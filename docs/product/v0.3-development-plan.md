## 1. Where June Stands Today

### What is solid (shipped and working)

- **Harness loop** — hand-written, single engine, 3-17x faster than the LangGraph predecessor (removed in ADR 0018). Fixed shape, dynamic choices as data.
- **Three-store memory** — sqlite-vec semantic index + structured SQLite rows + entity graph, behind one `MemoryManager` facade (ADR 0019).
- **Trust Ledger** — append-only, blake2b hash-chained, optional Ed25519 signing. Tamper-evident provenance for every cloud call and action.
- **Guard layer** — untrusted-content framing, secret redaction, taint tracking, action gates (ADR 0021). Structural defense is shipped.
- **Silence Model v1** — rules-first `now|batch|suppress` policy, ledger-auditable. Implements the fourth inversion.
- **Desktop shell** — Tauri 2 with PyInstaller sidecar, watchdog, corrupt-DB recovery, loopback auth.
- **Promises/tasks** — standing intentions with per-step trace, blocked-reason persistence, retries, recurrence.
- **908 backend tests, 7 Playwright specs.**
- **Four inversions as working code**, not just philosophy (ADR 0015).

## 2. Competitive Position

### Market landscape (July 2026)

| Competitor | Their strength | Their weakness | June's advantage |
|---|---|---|---|
| **Limitless.ai** (Meta) | Memory from meetings/calls | Being sunsetted; cloud-first | Local-first memory; fills the vacuum |
| **Mem.ai** | Compounding memory graph | Cloud-only, no agent extensibility | Local-first, MCP-capable, proactive |
| **Personal.ai** | Personal language model | $40/mo, reactive only | Open architecture, proactive, cheaper |
| **Apple Intelligence** | On-device processing | Ecosystem lock-in, no deep memory | Cross-platform, deeper memory |
| **Khoj** (OSS) | Self-hostable, multi-LLM | Document-focused, not conversation-focused | Conversation-first memory, character |
| **ChatGPT/Claude** | Best general intelligence | No persistent memory, no proactive | Persistent memory, proactive |

### Key market data

- **71%** of users rank memory persistence above voice, photos, and personality (Bae survey, April 2026)
- **63%** prefer an AI that pushes back over one that agrees with everything
- Users average **4.2 different AI assistants** — the future is multi-tool
- Memory is "the axis of competition" through 2027 — only 1/12 platforms tested had "robust" memory

### June's unique position

Nobody else combines: local-first + personal memory graph + proactive behavior +
honest character + open architecture. This is a defensible wedge.

## 3. Development Roadmap

### Phase 1: Foundation Fixes (Weeks 1-2)

Fix what is broken before building what is new.

| Task | Why it matters | Effort | Dependencies |
|---|---|---|---|
| **S2.3 — RRF Fusion Scoring** | Without this, migration v7's FTS5 + temporal columns are dead schema. Single highest-leverage commit. | High | Migration v7 (done) |
| **Fix version truth** | `app.py` says 0.2.0, pyproject says 0.0.0, Tauri says 0.1.0. One source of truth. | Low | None |
| **Drop LangChain dependencies** | ADR 0018 removed the engine but `tools.py` and `models.py` still use LangChain primitives. Replace with `tools_base.py`. | Medium | None |
| **Cloud egress enforcement gate** | Build blocking gate on `provenance.py` chokepoint. W3/W4 depend on this. | Medium | None |
| **Fix DuckDuckGo fallback** | Standardize on Brave API or build resilient multi-provider fallback. | Low | None |

### Phase 2: Memory Intelligence (Weeks 3-5)

Make memory the product — the feature nobody else delivers well.

| Task | Why it matters | Effort | Dependencies |
|---|---|---|---|
| **W2 completion: FTS5 triggers + BM25 scoring** | FTS5 table exists but has no triggers or BM25 helper. Wire it up. | Medium | S2.3 |
| **Four-signal fusion: vec + BM25 + entity + time** | RRF k=60, `RetrievalConfig` dataclass. This is the retrieval brain. | High | FTS5 triggers |
| **Golden retrieval test suite** | 100-case test set, >=10% recall@8 improvement, p95 < 120ms on 50k corpus. Release gate. | Medium | Fusion scoring |
| **W3: Memory provenance & quarantine** | `provenance`, `trust_level`, `quarantined`, `source_ref` columns. Untrusted memories trackable. | High | Egress gate |
| **Injection heuristic** | `guard/injection.py` — detect imperative-instruction patterns. Defense-in-depth alongside structural guards. | Medium | Guard layer (done) |
| **ADR 0025 + ADR 0026** | Provenance-gated writes and Night Shift vs. no-heartbeat reconciliation. Must be written before implementation. | Medium | None |

### Phase 3: Voice and Proactive (Weeks 6-9)

Cross the "chatbot vs assistant" gap.

| Task | Why it matters | Effort | Dependencies |
|---|---|---|---|
| **Voice I/O** | Table stakes by 2027. Whisper (local) for STT, Piper/Coqui for TTS, cloud fallback. On-device for privacy. | High | None |
| **Proactive briefings** | Daily summary, meeting prep, follow-up surfacing. Silence-Model-gated. What makes June an assistant not a chatbot. | High | Silence Model (done) |
| **W4: Night Shift** | Consolidation pipeline (7 stages, per-stage checkpointing). Requires ADR 0026 reconciliation with ADR 0016. | Very High | ADR 0026 |
| **Promise checkpoint/resume** | Current tasks re-run from scratch. Need real per-stage durable checkpointing. | High | None |
| **Calendar integration skill** | Connect to Google/Apple Calendar. Show meetings, prep context, suggest follow-ups. | Medium | None |

### Phase 4: Integration and Polish (Weeks 10-13)

Connect June to the user's life.

| Task | Why it matters | Effort | Dependencies |
|---|---|---|---|
| **MCP server** | Let ChatGPT/Claude/Khoj use June's memory as a tool. Validates multi-assistant positioning. | Medium | Memory system |
| **Email integration** | Read incoming emails, surface action items, draft responses. The #1 "assistant not chatbot" feature. | High | MCP server |
| **In-app update check** | GitHub Releases API, <=1/24h. First permitted non-model network call. | Low | Version truth |
| **Better onboarding** | Memory takes 4-8 weeks to feel useful. Guide users with a "memory tutorial" flow. | Medium | None |
| **Data export / portability** | Full export of memory graph. June's local-first approach wins against Mem's portability anxiety. | Medium | None |

### Phase 5: Desktop and Distribution (Weeks 14-16)

Ship a polished, installable product.

| Task | Why it matters | Effort | Dependencies |
|---|---|---|---|
| **Notarized DMG / code signing** | Infrastructure landed; needs Apple enrollment. Eliminates macOS security warnings. | Low | Apple enrollment |
| **Auto-update mechanism** | Tauri updater plugin. Users should not have to manually reinstall. | Medium | Update check |
| **Playwright e2e coverage** | v0.2 flows: provenance review, Night Shift report, update affordance, voice interaction. | Medium | Features above |
| **Performance audit** | Profile frontend re-renders, API response times, memory query latency. | Medium | None |
| **Accessibility pass** | ARIA labels, keyboard navigation, screen reader support. | Medium | None |

## 5. Strategic Recommendations

### Double down on

1. **Memory as the moat.** 71% of users want it, almost nobody delivers it well. Make retrieval intelligence (fusion scoring, temporal awareness, quarantine) the best-in-class feature.
2. **The four inversions.** Verified market demand: 63% want pushback. "Continues, not completes" solves the memory-reset problem everyone complains about.
3. **Local-first.** The Limitless sunset proves cloud-first memory is fragile. June's data stays on the user's machine.

### Build next

1. **Voice interaction** — by 2027 it is table stakes. Start with minimal STT/TTS pipeline.
2. **Proactive briefings** — separates "assistant" from "chatbot." Calendar-aware daily summaries, meeting prep, follow-up surfacing.
3. **MCP server** — positions June as infrastructure, not just an app.

### Avoid

1. **Do not become a general chatbot.** ChatGPT/Claude already won that. June's value is memory + character + proactive.
2. **Do not add a third cloud provider without explicit user consent.** ADR 0002's intent is clear.
3. **Do not accumulate without governance.** "Forgets, not accumulates" is a differentiator.
