# June v0.3 — Development Plan

**Created:** 2026-07-24. **Consolidated and re-ordered:** 2026-07-26.
**Status:** Active. The single plan of record.

This is the only plan document. It holds the *what*, the *why*, and the *order*,
because keeping those in separate files produced two docs that disagreed within
a day of each other. Where any other doc conflicts with this one, this one wins
and that one should be archived.

For the authoritative state of what is shipped, see [`../CURRENT.md`](../CURRENT.md).
For the durable worldview, see [`../vision.md`](../vision.md).

Every slice below is: one piece of work → `./tools/check.sh` green → one commit →
push. No batching. Slices are sized so none takes more than a day.

## 1. Where June stands

### Solid and shipped

- **Harness loop** — hand-written, single engine, fixed shape, dynamic choices as data (ADR 0018).
- **Three-store memory** — sqlite-vec index + structured rows + entity graph behind one `MemoryManager` facade, in one SQLite file (ADR 0019).
- **Retrieval v2, measured** — four-signal fusion beats vector-only recall@8 by **+29%** at 50k facts ([benchmark](retrieval-benchmark.md)).
- **Trust Ledger** — append-only, blake2b hash-chained, optional Ed25519 signing (ADR 0022).
- **Guard layer** — untrusted-content framing, secret redaction, taint tracking, action gates (ADR 0021).
- **Silence Model v1** — rules-first `now|batch|suppress`, ledger-auditable (ADR 0023).
- **Desktop shell** — Tauri 2 with a frozen Python sidecar, watchdog, corrupt-DB recovery, loopback auth.
- **Promises** — standing intentions with per-step trace, blocked-reason persistence, retries, recurrence.
- **MCP memory server** — read-only, consent-gated, ledgered (ADR 0030).
- **A working `v0.1.0` release**, verified end to end rather than assumed.
- **1001 backend tests, 8 Playwright specs**, and a green gate that runs in CI.

### Open defects

| Issue | Impact | Location |
|---|---|---|
| **Retrieval p95 is 252ms at 50k facts** | Misses the 120ms target; sqlite-vec runs a brute-force KNN whose cost is independent of `k`, so it grows linearly with memory size | `memory/vec_index.py` |
| **The temporal signal does not rank** | Ablating it changes nothing; ADR 0024 claims four signals but ships three and a filter | `memory/recall.py` |
| **`distractor_heavy` recall is 0.31** | The weakest category, and the shape most like real recall failure | golden corpus |
| **Promise resume re-runs the goal** | No mid-plan checkpoint; undercuts the "continues, not completes" inversion | `tasks/` |
| ~~**No injection heuristic**~~ | Fixed in Phase 5: `guard/injection.py`, measured at 100% recall / 3% FP on the corpus | `guard/injection.py` |
| **No in-app updates** | No channel to reach users who install | desktop shell |
| **Apple Silicon only** | Excludes every user of the platform the competition runs on | packaging |
| **`/setup` has no e2e coverage** | The first-run path every user takes | `apps/web/e2e/` |
| **Nothing tests the packaged binary** | A total chat hang passed 986 green tests; only running the DMG caught it | CI |
| **`.git` is 240MB** | History carries a v1 virtualenv, a 68MB checkpoint, MNIST | git history |

## 2. Competitive position

**Updated 2026-07-26.** The earlier version of this section listed Limitless,
Mem.ai, Personal.ai, Apple Intelligence, Khoj and ChatGPT/Claude, and concluded
that "local-first + memory + open architecture" was an unoccupied wedge. That
conclusion is no longer true.

| Competitor | Their strength | Their weakness |
|---|---|---|
| **OpenClaw** | ~353K stars, 3.2M users, 500K instances, 1,200 contributors in under 5 months. Local-first, self-hosted, 24 messaging channels, huge plugin ecosystem | 40,214 internet-exposed instances with 35.4% flagged vulnerable (SecurityScorecard, Feb 2026); CVEs for prompt-injection-driven code execution and CVSS 8.8 cookie exfiltration |
| **OpenMemory (Mem0)** | Local-first MCP memory server, works with Claude Desktop / Cursor / VS Code today | Memory only — no character, no proactivity, no audit trail |
| **Mem.ai, Personal.ai** | Compounding memory | Cloud-only; Personal.ai is $40/mo |
| **Apple Intelligence** | On-device | Ecosystem lock-in, shallow memory |
| **ChatGPT / Claude** | Best general intelligence | No persistent memory, no proactivity |

### What this means

June is **not** differentiated by being local-first and open-source. That race
has a winner at 3.2M users, and competing there is competing on their strength.

June **is** differentiated by being **auditable**: loopback-only with no external
listener, one guard seam every tool call passes, taint tracked across calls,
consequential actions gated behind approval, and a hash-chained record of
everything — including the decision to stay quiet. That is precisely the failure
class the incumbent is generating CVEs for, and it is already built and tested.

The positioning line moves from *"a local-first personal AI"* to
**"the agent that can prove what it did."**

### The uncomfortable number

835 commits over 16 months have produced **0 stars, 0 forks, 0 downloads**. The
constraint on this project has never been engineering quality. It is that nobody
has been given a reason or a route to try it. Every phase below is ordered by
that fact: reach before polish, evidence before assertion.

## 3. The plan

### Done

| Phase | Outcome |
|---|---|
| 0 — Reconcile the record | Plans matched to code; five "broken" items were already fixed |
| 1 — A download that works | Found and fixed a total chat hang in the packaged app (macOS Keychain blocking a headless sidecar); `v0.1.0` re-cut and verified |
| 2 — Prove the retrieval work | +29% recall@8 measured; latency gate failed and is documented; stop-word and candidate-pool defects found and fixed |

| 4 — MCP server | ADR 0030; read-only consent-gated ledgered server, grant CLI, rate limiting, Receipts surfacing, README quickstart |

### Phase 4 — June as infrastructure · **done**

The first path to trying June that needs no Mac and no 8GB download. ADR 0030,
a read-only consent-gated ledgered server, a `june-mcp` CLI for grants that
works with the app closed, per-client rate limiting, an "External reads" filter
in Receipts, and a README quickstart. 19 tests.

**Open follow-up:** `JUNE_MCP_CLIENT` is a declared name, not a proven identity.
A grant narrows blast radius and creates an audit trail; it does not authenticate
the caller. Closing it needs OS-level attestation of the calling process and
belongs with Phase 6.

### Phase 5 — Make the security claim checkable · 3-4 days

The guard layer is real but asserted in prose, and nobody audits prose.

| Slice | Work | Acceptance | Status |
|---|---|---|---|
| **5.1+5.2** | `guard/injection.py` plus the corpus that scores it. Merged: a threshold cannot be chosen without a corpus, and a corpus scores nothing without a detector | 30/30 attack shapes caught, 1/32 benign flagged, 0.32ms per 13.5k chars ([benchmark](injection-benchmark.md)) | **done** |
| **5.3** | Detection wired into the guard seam — a flagged result revokes standing approvals | An "always allow" stops covering a tool once a poisoned result lands; tainted `execute` no longer waivable | **done** |
| **5.4** | Ledger verification CLI | `june-verify` exits non-zero on tampering; `--export` hands the chain to a third party ([how](trust-ledger-verification.md)) | **done** |
| **5.5** | Published threat model: what June's architecture stops, what it does not, residual risks | [Written](../security/threat-model.md) gaps-first, every defence citing its code and test; `SECURITY.md` rewritten (it still described Chroma and Gemini) | **done** |

**Phase 5 found one High-severity gap in June's own design**, recorded in the
threat model and not yet fixed: the action gate classifies tool calls by *naming
convention*, so a skill advertising a network tool as `get_something` executes
without an approval prompt. Manifest scope-drift detection uses the same
name-based classifier and reports rather than blocks, so a consistently
mislabelled skill produces no drift. Fixing it needs capability declaration
enforced at dispatch. Scheduled into Phase 6, which is already the provenance
phase.

| **6.4** | `/memory` shows where each fact came from | Visible in the UI |

## 4. Standing rules

- **Graceful degradation ships in the same change** as any model-judgment feature.
- **Every privacy-boundary change is documented in the commit that makes it.**
- **ADR before implementation** for anything touching the boundary or the stores.
- `./tools/check.sh` green before every push, read directly, never through a pipe.
- Accessibility and Playwright coverage extend with each surface, not in a
  sprint at the end.
